**Módulo Médico**

# 1. Objetivo

El módulo Médico será el espacio principal de trabajo clínico para los profesionales médicos dentro de Reimbow HIS.

Permitirá consultar pacientes, realizar valoraciones, documentar la atención, establecer diagnósticos, generar indicaciones, prescribir medicamentos, solicitar estudios, solicitar interconsultas, realizar procedimientos, preparar egresos y dar seguimiento a la evolución clínica.

El módulo deberá adaptarse al nivel de responsabilidad y atribuciones de cada usuario.

Inicialmente se contemplarán:

- Médico tratante.

- Médico adscrito.

- Médico especialista.

- Médico de guardia.

- Médico residente.

- Médico interno de pregrado.

- Médicos con funciones de supervisión.

- Médicos interconsultantes.

La arquitectura deberá permitir incorporar posteriormente otros perfiles médicos.

# 2. Principios del módulo

El módulo Médico deberá diseñarse bajo los siguientes principios:

- Seguridad del paciente.

- Identificación correcta.

- Responsabilidad individual.

- Autoría identificable.

- Supervisión del personal en formación.

- Trazabilidad.

- Prescripción segura.

- Continuidad asistencial.

- Información clínica estructurada.

- Reducción de errores.

- Evitar duplicación innecesaria de información.

- Integración con el expediente clínico.

- Comunicación efectiva.

- Respeto a los privilegios clínicos.

- Auditoría de acciones.

- Conservación de las diferentes versiones de documentos.

# 4. Tipos de médico

## 4.1 Médico tratante

Profesional responsable principal de la atención del paciente durante determinado episodio.

Podrá:

- Consultar el expediente.

- Elaborar y firmar notas.

- Establecer diagnósticos.

- Prescribir.

- Solicitar estudios.

- Solicitar interconsultas.

- Indicar procedimientos.

- Modificar tratamientos.

- Suspender tratamientos.

- Elaborar alta.

- Supervisar personal en formación cuando esté autorizado.

## 4.2 Médico adscrito

Profesional asignado a un servicio hospitalario.

Sus permisos dependerán de:

- Servicio.

- Especialidad.

- Turno.

- Privilegios clínicos.

- Relación con el paciente.

Podrá funcionar como supervisor de:

- Médicos residentes.

- Médicos internos.

- Otros médicos en formación.

## 4.3 Médico de guardia

Tendrá acceso a los pacientes correspondientes a su servicio durante el periodo de guardia.

Deberá poder:

- Valorar pacientes.

- Atender urgencias.

- Elaborar notas.

- Prescribir.

- Modificar indicaciones.

- Solicitar estudios.

- Documentar eventos.

- Recibir entrega de pacientes.

Su intervención quedará registrada independientemente de que no sea el médico tratante habitual.

# 5. Médico residente

El sistema deberá distinguir al médico residente del médico adscrito.

El nivel de autonomía podrá configurarse dependiendo de:

- Institución.

- Especialidad.

- Año de residencia.

- Servicio.

- Procedimiento.

- Tipo de documento.

- Privilegios otorgados.

Ejemplo:

Residente R1

→ Supervisión alta

Residente R2

→ Supervisión definida por actividad

Residente R3/R4

→ Mayor autonomía

Adscripción

→ Supervisión según privilegios

No deberán codificarse estas reglas permanentemente en el software.

La institución podrá configurarlas.

# 6. Médico Interno de Pregrado

Reimbow HIS tendrá un perfil específico:

MÉDICO INTERNO DE PREGRADO

MIP

El MIP será considerado un usuario clínico en formación.

Podrá participar en la documentación y actividades que la institución le permita, pero **toda actividad clínica que genere deberá quedar sometida a revisión por un médico autorizado antes de adquirir carácter definitivo dentro del sistema**.

Esta será una regla fundamental de Reimbow HIS.

# 8. Autoría del Médico Interno

Que una nota necesite supervisión no significa que desaparezca la autoría del interno.

Esto será especialmente importante.

Si:

MIP María López

escribe una nota y:

Dr. Juan Pérez

la revisa, el sistema deberá conservar ambas intervenciones.

Nunca deberá aparecer como si el Dr. Juan Pérez hubiese escrito originalmente la nota.

# 17. Modificación directa por el supervisor

Podrán existir dos modelos institucionales.

**Modelo A — Corrección por el interno**

El supervisor solicita modificaciones y el interno corrige.

Será el modelo preferido cuando la situación lo permita porque mantiene claramente el proceso formativo.

**Modelo B — Corrección por el supervisor**

En situaciones donde sea necesario actuar rápidamente, el médico podrá modificar o complementar el documento.

Pero el sistema deberá señalarlo.

Ejemplo:

Elaboración inicial:

MIP María López

Modificación durante revisión:

Dr. Juan Pérez

Revisión y firma:

Dr. Juan Pérez

Nunca deberá atribuirse al interno contenido escrito posteriormente por otra persona.

# 24. Situaciones urgentes

La supervisión informática no deberá retrasar una emergencia.

Los protocolos institucionales deberán definir cómo actuar ante situaciones urgentes.

El sistema podrá disponer de mecanismos especiales para que un médico autorizado valide inmediatamente órdenes o acciones necesarias.

El software nunca deberá convertir un flujo administrativo de firma en un obstáculo para la atención urgente.

# 62. Requisitos funcionales iniciales

MED-RF-001

El sistema deberá mostrar al médico los pacientes correspondientes a su ámbito de atención.

MED-RF-002

El sistema deberá permitir elaborar notas médicas.

MED-RF-003

El sistema deberá permitir establecer diagnósticos.

MED-RF-004

El sistema deberá permitir generar indicaciones médicas.

MED-RF-005

El sistema deberá permitir realizar prescripciones estructuradas.

MED-RF-006

El sistema deberá permitir solicitar estudios.

MED-RF-007

El sistema deberá permitir solicitar y responder interconsultas.

MED-RF-008

El sistema deberá permitir iniciar el proceso de alta médica.

MED-RF-009

El sistema deberá mostrar resultados nuevos y críticos.

MED-RF-010

El sistema deberá permitir realizar entrega estructurada de pacientes.

MED-RF-011

El sistema deberá controlar acciones según privilegios clínicos.

MED-RF-012

El sistema deberá disponer de un perfil específico para Médico Interno de Pregrado.

MED-RF-013

Todo documento elaborado por un MIP deberá requerir revisión de un médico autorizado antes de adquirir estado definitivo.

MED-RF-014

El sistema deberá conservar la identidad del MIP que elaboró el documento.

MED-RF-015

El sistema deberá registrar al médico que revisó y validó el documento.

MED-RF-016

El documento final deberá mostrar claramente quién lo elaboró y quién lo revisó y firmó.

MED-RF-017

El MIP no deberá poder firmar autónomamente un documento definitivo bajo la política inicial del sistema.

MED-RF-018

Las propuestas terapéuticas realizadas por un MIP no deberán convertirse en órdenes ejecutables antes de su validación.

MED-RF-019

El sistema deberá permitir al supervisor solicitar correcciones.

MED-RF-020

El sistema deberá mantener el historial de versiones durante el proceso de supervisión.

MED-RF-021

El sistema deberá impedir que la modificación del supervisor sea atribuida incorrectamente al MIP.

MED-RF-022

El sistema deberá permitir asignar supervisores por rotación, servicio y turno.

MED-RF-023

El sistema deberá registrar fecha y hora de elaboración, envío, revisión y firma.

MED-RF-024

Una nota supervisada y firmada sólo podrá corregirse posteriormente mediante los mecanismos establecidos para el expediente clínico.

# 63. Requisitos no funcionales iniciales

MED-RNF-001

Las acciones clínicas deberán estar sujetas a permisos y privilegios.

MED-RNF-002

La autoría original de los documentos deberá preservarse.

MED-RNF-003

La supervisión deberá ser completamente auditable.

MED-RNF-004

Las órdenes pendientes de supervisión no deberán ser ejecutables.

MED-RNF-005

La interfaz deberá distinguir claramente propuestas, borradores y órdenes válidas.

MED-RNF-006

La supervisión informática no deberá impedir la atención de situaciones urgentes.

MED-RNF-007

Los documentos firmados deberán conservar su integridad.

MED-RNF-008

El sistema deberá soportar múltiples niveles futuros de supervisión.

MED-RNF-009

Las reglas de autonomía deberán ser configurables por institución.

MED-RNF-010

El sistema deberá mantener una separación explícita entre autoría, revisión y autorización.

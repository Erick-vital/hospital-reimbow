**Módulo de Admisión**

# 1. Objetivo

El módulo de Admisión será responsable de registrar y controlar el ingreso de los pacientes a la institución, vincular cada atención con un paciente correctamente identificado y generar el episodio asistencial correspondiente.

También deberá coordinar la asignación inicial de servicio, médico, ubicación física, cama, modalidad de atención y cuenta administrativa.

Admisión será el punto de entrada para los siguientes módulos:

- Expediente clínico.

- Médico.

- Enfermería.

- Urgencias.

- Hospitalización.

- Estudios diagnósticos.

- Farmacia.

- Nutrición.

- Cuentas.

- Caja.

- Aseguradoras y convenios.

- Trabajo social.

- Egreso.

- Calidad y seguridad del paciente.

# 2. Principios del módulo

El diseño deberá cumplir los siguientes principios:

- Identificación correcta del paciente.

- Prevención de registros duplicados.

- Trazabilidad de ingresos y movimientos.

- Separación entre paciente y episodio de atención.

- Protección de datos personales.

- Continuidad del expediente clínico.

- Disponibilidad rápida en situaciones de urgencia.

- Integración clínica y administrativa.

- Registro cronológico.

- Control de camas y ubicaciones.

- Auditoría de modificaciones.

- Capacidad para registrar pacientes no identificados.

# 3. Diferencia entre paciente y admisión

## 3.1 Paciente

Representa a la persona dentro del sistema.

El registro del paciente deberá ser único y conservarse durante toda su relación con la institución.

Ejemplos de información asociada al paciente:

- Nombre.

- Apellidos.

- Fecha de nacimiento.

- Sexo.

- CURP.

- Nacionalidad.

- Datos de contacto.

- Domicilio.

- Contactos de emergencia.

- Alergias conocidas.

- Identificadores institucionales.

- Expediente clínico histórico.

## 3.2 Admisión

Representa una atención específica.

Ejemplos:

- Consulta externa.

- Atención de urgencias.

- Hospitalización.

- Cirugía ambulatoria.

- Estudio diagnóstico.

- Rehabilitación.

- Atención domiciliaria.

Cada nueva atención deberá crear un episodio independiente, relacionado con el mismo paciente.

Ejemplo:

Paciente: PAC-000012

Episodios:

\- URG-2026-000245

\- HOS-2026-000138

\- CE-2026-001785

Esto permitirá conservar la continuidad del paciente sin mezclar todas sus atenciones en un solo registro operativo.

# 4. Tipos de admisión

El sistema deberá manejar diferentes modalidades.

## 4.1 Consulta externa

Para pacientes con atención programada o ambulatoria.

Puede incluir:

- Consulta médica.

- Consulta de especialidad.

- Nutrición.

- Psicología.

- Rehabilitación.

- Clínica del dolor.

- Curaciones.

- Procedimientos menores.

## 4.2 Urgencias

Para atención inmediata o no programada.

Debe permitir:

- Registro rápido.

- Paciente identificado.

- Paciente parcialmente identificado.

- Paciente desconocido.

- Clasificación de triage.

- Asignación a consultorio, observación, choque o reanimación.

- Conversión posterior a hospitalización.

## 4.3 Hospitalización

Para pacientes que requieren estancia intrahospitalaria.

Debe registrar:

- Servicio de ingreso.

- Médico tratante.

- Diagnóstico o motivo inicial.

- Habitación.

- Cama.

- Fecha y hora de ingreso.

- Procedencia.

- Tipo de financiamiento.

## 4.4 Cirugía ambulatoria

Para pacientes que ingresan para un procedimiento y egresan el mismo día.

Debe relacionarse con:

- Programación quirúrgica.

- Cirujano.

- Anestesiólogo.

- Procedimiento.

- Quirófano.

- Recuperación.

- Alta.

## 4.5 Corta estancia

Para pacientes que requieren vigilancia limitada sin hospitalización convencional.

## 4.6 Estudios diagnósticos

Para pacientes externos que únicamente acuden a:

- Laboratorio.

- Imagenología.

- Cultivos.

- Patología.

- Otros estudios.

## 4.7 Atención administrativa

Podría utilizarse para trámites sin atención clínica directa, por ejemplo:

- Solicitud de copia de expediente.

- Certificados.

- Valoraciones administrativas.

- Revisión de documentos.

No necesariamente deberá abrir un episodio clínico completo.

# 6. Búsqueda previa del paciente

Antes de crear un nuevo paciente, el sistema deberá obligar a realizar una búsqueda.

La búsqueda podrá utilizar:

- Número de expediente.

- CURP.

- Nombre completo.

- Fecha de nacimiento.

- Teléfono.

- Correo electrónico.

- Identificación oficial.

- Identificador externo.

- Combinaciones fonéticas o aproximadas.

El sistema deberá advertir posibles coincidencias.

Ejemplo:

Posible paciente duplicado

Nombre: Juan Carlos Pérez López

Fecha de nacimiento: 14/03/1965

Coincidencia estimada: 92 %

PAC-000128

PAC-000763

El usuario deberá revisar antes de crear un nuevo registro.

# 7. Prevención de duplicados

La duplicidad de pacientes puede provocar:

- Fragmentación del expediente.

- Pérdida de antecedentes.

- Errores de medicación.

- Resultados asociados a otra persona.

- Facturación incorrecta.

- Riesgos médico-legales.

El sistema deberá utilizar reglas de detección basadas en:

- CURP idéntica.

- Nombre y fecha de nacimiento.

- Teléfono.

- Identificación oficial.

- Combinación de apellidos.

- Coincidencia fonética.

- Sexo y lugar de nacimiento.

No se deberá fusionar automáticamente a dos pacientes.

La fusión deberá:

- Requerir permiso especial.

- Mostrar ambos registros.

- Solicitar confirmación.

- Conservar una bitácora.

- Mantener los identificadores anteriores.

- Permitir investigación posterior.

# 8. Identificación correcta del paciente

El sistema deberá utilizar al menos dos identificadores confiables para confirmar al paciente.

Ejemplos:

- Nombre completo.

- Fecha de nacimiento.

- CURP.

- Número de expediente.

La habitación, cama o ubicación no deberán utilizarse como identificadores personales, porque pueden cambiar durante la atención.

La identificación correcta es una de las Acciones Esenciales para la Seguridad del Paciente y debe aplicarse desde el ingreso y durante todo el proceso asistencial.

# 9. Paciente desconocido

Urgencias deberá permitir registrar pacientes cuya identidad sea desconocida.

Ejemplo:

Paciente desconocido

Sexo aparente: masculino

Edad aparente: 40–50 años

Fecha y hora de ingreso: 22/07/2026 23:12

Procedencia: vía pública

Traslado: ambulancia

Identificador provisional: DESC-2026-00014

El registro deberá permitir:

- Capturar características físicas.

- Adjuntar fotografía institucional si está autorizada.

- Registrar pertenencias.

- Identificar quién realizó el traslado.

- Registrar autoridad o ambulancia responsable.

- Crear brazalete provisional.

- Brindar atención inmediata.

- Actualizar posteriormente la identidad.

Cuando se confirme la identidad, el episodio provisional deberá vincularse al paciente correcto sin perder el historial generado.

La normativa de seguridad del paciente contempla que las instituciones tengan un procedimiento específico para pacientes desconocidos o incapaces de proporcionar su identidad.

# 10. Datos del episodio de atención

Cada admisión deberá contener, como mínimo:

**Identificación del episodio**

- Folio de admisión.

- Tipo de atención.

- Fecha y hora de ingreso.

- Sede.

- Servicio.

- Estado del episodio.

- Procedencia.

- Prioridad.

**Información clínica inicial**

- Motivo de atención.

- Diagnóstico inicial, cuando exista.

- Médico responsable.

- Especialidad.

- Tipo de ingreso.

- Información de triage, cuando corresponda.

**Información administrativa**

- Tipo de paciente.

- Particular.

- Aseguradora.

- Convenio.

- Empresa.

- Institución pública.

- Beneficiario.

- Póliza.

- Número de autorización.

- Responsable de pago.

**Ubicación**

- Área.

- Servicio.

- Habitación.

- Cama.

- Consultorio.

- Cubículo.

- Sala.

**Contacto**

- Familiar responsable.

- Contacto de emergencia.

- Teléfono.

- Relación con el paciente.

- Persona autorizada para recibir información.

# 11. Datos demográficos del paciente

El registro maestro podría incluir:

- Nombre o nombres.

- Primer apellido.

- Segundo apellido.

- Fecha de nacimiento.

- Sexo registrado.

- Identidad de género, cuando sea relevante y se determine su tratamiento.

- CURP.

- RFC, si es necesario administrativamente.

- Nacionalidad.

- Estado civil.

- Ocupación.

- Religión, únicamente cuando sea voluntaria y clínicamente relevante.

- Lengua o idioma preferente.

- Necesidad de intérprete.

- Escolaridad.

- Teléfono.

- Correo.

- Domicilio.

- Identificación oficial.

No todos los campos deberán ser obligatorios en una urgencia.

El sistema deberá distinguir:

Dato desconocido

Dato no proporcionado

Dato no aplica

Dato pendiente de verificar

Esto es mejor que completar información falsa únicamente para avanzar.

# 12. Datos sensibles y acceso restringido

El personal de Admisión deberá acceder sólo a la información necesaria.

Podrá consultar:

- Datos demográficos.

- Identificadores.

- Contactos.

- Aseguradora.

- Episodios previos básicos.

- Alertas indispensables para identificación.

No deberá consultar libremente:

- Notas médicas completas.

- Diagnósticos sensibles.

- Resultados de laboratorio.

- Información de salud mental.

- Información clínica no necesaria para su trabajo.

La NOM-004 establece que los datos personales que permiten identificar al paciente deben manejarse con confidencialidad dentro del expediente clínico.

# 13. Asignación de servicio

El episodio deberá vincularse con un servicio responsable.

Ejemplos:

- Medicina interna.

- Cirugía.

- Pediatría.

- Ginecología y obstetricia.

- Traumatología.

- Terapia intensiva.

- Urgencias.

- Consulta externa.

- Oncología.

- Rehabilitación.

El servicio puede cambiar durante la atención, pero el sistema deberá conservar el historial.

Ejemplo:

22/07/2026 09:15 — Urgencias

22/07/2026 14:32 — Medicina interna

24/07/2026 18:10 — Terapia intensiva

# 14. Asignación de médico

Se deberá distinguir entre:

- Médico que admite.

- Médico tratante.

- Médico responsable del servicio.

- Médico interconsultante.

- Médico de guardia.

- Cirujano.

- Anestesiólogo.

El médico tratante podrá cambiar, pero todo cambio deberá quedar registrado.

# 15. Gestión de habitaciones y camas

Admisión deberá integrarse con un mapa de ocupación.

Estados posibles de una cama:

Disponible

Reservada

Ocupada

En limpieza

Bloqueada

En mantenimiento

Aislada

No disponible

La asignación deberá verificar:

- Disponibilidad.

- Tipo de habitación.

- Sexo, según políticas institucionales.

- Edad.

- Tipo de servicio.

- Aislamiento.

- Riesgo infeccioso.

- Requerimientos de oxígeno.

- Nivel de atención.

- Convenio o paquete contratado.

No se deberá ocupar una cama que aparezca como:

- En limpieza.

- En mantenimiento.

- Bloqueada.

- Asignada a otro paciente.

# 16. Reserva de cama

El sistema deberá permitir reservar una cama para:

- Cirugía programada.

- Traslado desde otra institución.

- Ingreso electivo.

- Cambio de servicio.

- Paciente de urgencias pendiente de hospitalización.

La reserva deberá tener:

- Paciente.

- Motivo.

- Usuario responsable.

- Hora de reserva.

- Tiempo de expiración.

- Prioridad.

- Estado.

Las reservas no utilizadas deberán expirar o requerir renovación para evitar falsas ocupaciones.

# 17. Traslados internos

Admisión o el personal autorizado deberá registrar movimientos internos:

- Cambio de cama.

- Cambio de habitación.

- Cambio de piso.

- Cambio de servicio.

- Traslado a terapia intensiva.

- Traslado a quirófano.

- Traslado a recuperación.

- Traslado temporal a estudios.

Debe distinguirse entre:

**Ubicación administrativa**

Lugar al que pertenece formalmente el paciente.

**Ubicación temporal**

Lugar donde se encuentra en ese momento.

Ejemplo:

Ubicación administrativa:

Habitación 205, cama A

Ubicación temporal:

Tomografía

Esto evita que un paciente aparezca erróneamente como ausente de su cama durante un procedimiento.

# 18. Brazalete e identificación física

Después del ingreso, el sistema deberá poder generar un brazalete con:

- Nombre completo.

- Fecha de nacimiento.

- Número de expediente.

- Folio del episodio.

- Código de barras o QR.

- Alertas institucionales autorizadas.

El código no deberá exponer directamente información clínica sensible.

El brazalete podrá utilizarse para:

- Confirmar identidad.

- Administrar medicamentos.

- Tomar muestras.

- Realizar procedimientos.

- Trasladar al paciente.

- Vincular resultados.

# 19. Documentos de admisión

El módulo deberá gestionar los documentos administrativos relacionados con el ingreso:

- Identificación oficial.

- CURP.

- Comprobante de domicilio.

- Póliza de seguro.

- Carta de autorización.

- Aviso de privacidad.

- Contrato de prestación de servicios.

- Reglamento hospitalario.

- Consentimientos administrativos.

- Responsiva.

- Documentos del responsable de pago.

Los documentos clínicos y consentimientos médicos deberán quedar relacionados con el expediente clínico, aunque puedan iniciarse desde Admisión.

# 20. Aseguradoras y convenios

El sistema deberá permitir registrar:

- Aseguradora.

- Número de póliza.

- Vigencia.

- Titular.

- Beneficiario.

- Suma asegurada.

- Deducible.

- Coaseguro.

- Número de siniestro.

- Carta de autorización.

- Servicios autorizados.

- Exclusiones.

- Ejecutivo o contacto.

- Estado de la autorización.

Estados posibles:

Pendiente

En revisión

Autorizada

Autorizada parcialmente

Rechazada

Vencida

La información clínica necesaria para una autorización deberá compartirse sólo con usuarios autorizados.

# 21. Apertura de cuenta

Cada episodio que genere cargos deberá relacionarse con una cuenta.

La cuenta deberá abrirse automáticamente o mediante confirmación, según la modalidad de atención.

Ejemplo:

Episodio: HOS-2026-00138

Cuenta: CTA-2026-00138

Responsable de pago: Particular

Estado: Abierta

Admisión podrá capturar la información inicial, pero los cargos y pagos corresponderán al módulo de Cuentas y Caja.

# 22. Estados de una admisión

El episodio podrá tener los siguientes estados:

Pre-admisión

Pendiente de documentación

Pendiente de autorización

Admitido

En atención

En observación

Hospitalizado

En traslado

Pre-egreso

Egresado

Cancelado

Referido

Defunción

Cada cambio de estado deberá registrar:

- Estado anterior.

- Estado nuevo.

- Fecha y hora.

- Usuario.

- Motivo.

- Área de origen.

- Área de destino.

# 23. Pre-admisión

La pre-admisión permitirá preparar ingresos programados.

Aplicaciones:

- Cirugías.

- Estudios.

- Hospitalización electiva.

- Procedimientos.

- Partos programados.

Incluye:

- Captura anticipada de datos.

- Validación de documentos.

- Verificación de póliza.

- Reserva de cama.

- Programación.

- Generación de presupuesto.

- Indicaciones previas.

La pre-admisión no deberá considerarse ingreso efectivo hasta que el paciente se presente y sea confirmado.

# 24. Conversión entre tipos de atención

El sistema deberá permitir conversiones sin crear registros inconexos.

Ejemplos:

Urgencias → Hospitalización

Consulta externa → Urgencias

Cirugía ambulatoria → Hospitalización

Observación → Terapia intensiva

La conversión podrá:

- Mantener el mismo episodio con subepisodios.

- Crear un episodio relacionado.

La decisión definitiva deberá establecerse en la arquitectura, pero siempre deberá conservarse el vínculo entre las atenciones.

# 25. Cancelación de una admisión

Una admisión no deberá eliminarse.

Se marcará como cancelada y deberá registrarse:

- Motivo.

- Usuario.

- Fecha y hora.

- Estado previo.

- Si existieron cargos.

- Si existieron notas clínicas.

- Si se generó expediente.

- Si el paciente recibió atención.

No deberá permitirse cancelar libremente un episodio con actividad clínica firmada.

# 26. Corrección de datos

Los datos demográficos podrán corregirse con permisos específicos.

Debe distinguirse entre:

**Corrección simple**

Ejemplos:

- Error ortográfico.

- Teléfono.

- Correo.

- Domicilio.

**Corrección crítica**

Ejemplos:

- Nombre completo.

- Fecha de nacimiento.

- CURP.

- Sexo.

- Identificación.

- Cambio del paciente asociado al episodio.

Las correcciones críticas deberán:

- Solicitar motivo.

- Conservar valor anterior.

- Registrar usuario.

- Requerir autorización adicional.

- Generar una alerta de auditoría.

# 27. Fallecimiento

Admisión podrá visualizar el estado de defunción, pero la declaración clínica deberá ser realizada por personal médico autorizado.

Después de la confirmación médica, el sistema podrá habilitar:

- Fecha y hora de defunción.

- Médico certificante.

- Aviso a familiares.

- Trabajo social.

- Liberación de cama.

- Traslado a mortuorio.

- Cierre de cuenta.

- Documentación correspondiente.

Admisión no deberá registrar por sí sola una defunción clínica sin la validación médica necesaria.

# 28. Roles del módulo

**Recepcionista o admisión**

Puede:

- Buscar pacientes.

- Crear pacientes.

- Actualizar datos administrativos.

- Crear pre-admisiones.

- Crear episodios.

- Asignar servicio.

- Adjuntar documentos.

- Consultar disponibilidad.

**Supervisor de admisión**

Puede además:

- Autorizar correcciones críticas.

- Revisar duplicados.

- Gestionar fusiones.

- Cancelar admisiones.

- Revisar movimientos.

- Resolver inconsistencias.

**Coordinador de camas**

Puede:

- Asignar camas.

- Reservar camas.

- Bloquear camas.

- Registrar traslados.

- Consultar ocupación.

**Caja**

Puede:

- Consultar la admisión.

- Abrir cuentas.

- Registrar pagos.

- Consultar responsable financiero.

**Personal clínico**

Puede:

- Consultar datos esenciales de admisión.

- Ver servicio y ubicación.

- Confirmar identidad.

- Solicitar cambios de ubicación.

- No modificar libremente datos administrativos críticos.

# 30. Alertas del módulo

El módulo podrá generar alertas por:

- Posible paciente duplicado.

- CURP duplicada.

- Documento vencido.

- Póliza vencida.

- Autorización pendiente.

- Falta de contacto de emergencia.

- Paciente desconocido.

- Cama aún no asignada.

- Reserva próxima a expirar.

- Datos críticos incompletos.

- Paciente con homónimo.

- Cambio de identidad.

- Cuenta no abierta.

- Paciente pendiente de egreso administrativo.

Las alertas deberán clasificarse como:

Informativa

Advertencia

Importante

Bloqueante

No todas las alertas deberán impedir avanzar, especialmente en urgencias.

# 31. Reglas para urgencias

La falta de documentos o datos administrativos no deberá impedir una atención urgente.

En urgencias, el sistema deberá permitir:

- Registro mínimo.

- Identificador provisional.

- Atención inmediata.

- Apertura de episodio.

- Asignación rápida.

- Captura posterior de información.

- Regularización administrativa.

El sistema deberá señalar los datos pendientes, pero no bloquear la atención clínica.

**Aseguradoras**

Para registrar autorizaciones y coberturas.

# 37. Requisitos funcionales iniciales

ADM-RF-001

El sistema deberá permitir buscar un paciente antes de crear uno nuevo.

ADM-RF-002

El sistema deberá mostrar posibles coincidencias para prevenir duplicados.

ADM-RF-003

El sistema deberá permitir crear un episodio de atención vinculado a un paciente.

ADM-RF-004

El sistema deberá permitir registrar pacientes desconocidos en urgencias.

ADM-RF-005

El sistema deberá permitir asignar servicio, ubicación y cama.

ADM-RF-006

El sistema deberá mantener un historial de movimientos internos.

ADM-RF-007

El sistema deberá permitir convertir una atención de urgencias en hospitalización.

ADM-RF-008

El sistema deberá permitir crear pre-admisiones.

ADM-RF-009

El sistema deberá impedir que una cama no disponible sea asignada.

ADM-RF-010

El sistema deberá auditar las modificaciones de identidad y admisión.

# 38. Requisitos no funcionales iniciales

ADM-RNF-001

El sistema deberá permitir una admisión de urgencias aun cuando existan datos administrativos pendientes.

ADM-RNF-002

La búsqueda de pacientes deberá responder rápidamente con grandes volúmenes de registros.

ADM-RNF-003

Las modificaciones críticas deberán conservar el valor anterior.

ADM-RNF-004

El acceso a los datos deberá depender de los permisos del usuario.

ADM-RNF-005

El sistema deberá evitar la eliminación física de episodios y pacientes.

ADM-RNF-006

El módulo deberá mantener trazabilidad de todos los movimientos de cama.

ADM-RNF-007

La información clínica no necesaria no deberá mostrarse al personal administrativo.

# 39. Decisiones pendientes de la Fase -1

Antes de programar deberán definirse:

- Identificador institucional del paciente.

- Formato de folios de admisión.

- Campos obligatorios por modalidad.

- Reglas exactas para detectar duplicados.

- Procedimiento de fusión.

- Modelo de episodios y subepisodios.

- Estados oficiales de camas.

- Tiempo de expiración de reservas.

- Responsables de asignación de camas.

- Reglas para pacientes desconocidos.

- Datos visibles para Admisión.

- Flujo de aseguradoras.

- Integración entre alta médica y egreso administrativo.

- Política para brazaletes.

- Catálogos institucionales.
